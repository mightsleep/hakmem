1//! How the shipped kernels were composed, so you can compose your own.
2//!
3//! This module is documentation only. Every recipe has the same shape:
4//! the **problem**, the **decomposition** into combinators, the
5//! **laws** that justify each step (all of them live in [`crate::laws`]
6//! and run in the test suite), and the **cost** in word operations.
7//! Snippets are doctests, so the text cannot drift from the code.
8//!
9//! # Reading a sentence
10//!
11//! A register is a container of `BITS` cells. Each instruction is one
12//! of five shapes, and a kernel is a short sentence in them:
13//!
14//! | shape | combinators | what it does to the container |
15//! |---|---|---|
16//! | map | `and`, `or`, `xor`, `not`, `delta_swap` | every cell independently, or a fixed permutation |
17//! | scan | `wrapping_add`, `prefix_xor`, `prefix_or`, `fill_up` | information flows along the word (the carry chain is the scan primitive) |
18//! | filter | `compact`, `expand` | keep the cells a mask selects, in order |
19//! | reduce | `count_ones`, `trailing_zeros`, `select`, `longest_run` | one number out |
20//! | window | `run_starts`, `zero_bytes`, `bytes_eq` | a predicate over each cell's neighbourhood, all cells at once |
21//!
22//! The economics that make sentences worth writing: one cache miss is
23//! worth ~300 chained word operations, and a modern core retires four
24//! to six independent ones per cycle. A sentence of twelve operations
25//! that replaces a loop over sixty-four cells changes the complexity
26//! class per word.
27//!
28//! # Verifying your own
29//!
30//! Write the law before the kernel. A law is a `fn(...) -> bool` over
31//! `W: Word` comparing your combinator against a bit-by-bit loop (see
32//! `laws::reference`). Run it with proptest on `u64`, and exhaustively
33//! on `u8` / `u16`, every kernel in this crate that had a bug was
34//! caught by the exhaustive sweep, not by proptest. Then run the whole
35//! thing with and without `-C target-feature=+bmi2,+pclmulqdq`; the
36//! hardware and portable paths must agree bit for bit.
37//!
38//! ---
39//!
40//! # 1. The inside-string mask (simdjson)
41//!
42//! **Problem.** Given the positions of `"` and `\` in a block of text,
43//! which bytes are inside a string literal? Quotes preceded by an odd
44//! number of backslashes are escaped and do not count.
45//!
46//! **Decomposition.** Escaped positions are the ends of odd-length
47//! backslash runs: [`crate::Bits::find_escaped`], a carry-chain trick, runs
48//! starting on even and on odd positions are added separately, so each
49//! run's end parity falls out of an alternating mask. Real quotes are
50//! `quotes & !escaped`. Each real quote *toggles* the in-string state,
51//! and a toggle mask becomes a region mask by [`crate::Bits::prefix_xor`]
52//! (PCLMULQDQ by all-ones, or a smear).
53//!
54//! ```
55//! use hakmem::Bits;
56//!
57//! // text:    a " b \ " c " d
58//! // index:   0 1 2 3 4 5 6 7
59//! let quotes: u8 = 0b0101_0010;
60//! let backslashes: u8 = 0b0000_1000;
61//! let (escaped, _carry) = backslashes.find_escaped(false);
62//! let real = quotes & !escaped; // the quote at 4 is escaped
63//! let inside = real.prefix_xor();
64//! assert_eq!(inside, 0b0011_1110); // bytes 1..=5 are in the string
65//! ```
66//!
67//! **Laws.** `find_escaped_matches_reference` (parity walk, carry
68//! included); `prefix_xor_after_delta_is_identity` and its converse:
69//! toggles and regions are inverse views, so nothing is lost either
70//! way; `xor_linear_combinators`, `prefix_xor` distributes over XOR,
71//! which is why two independent toggle masks can be combined first and
72//! scanned once.
73//!
74//! **Cost.** `find_escaped` is ~14 operations with two additions;
75//! `prefix_xor` is one instruction with PCLMULQDQ, six otherwise. Per
76//! 64 bytes of text.
77//!
78//! # 2. First fit of a run across words
79//!
80//! **Problem.** In a bitmap of free slots, find the lowest position
81//! where `k` consecutive slots are free, when the run may straddle a
82//! word boundary.
83//!
84//! **Decomposition.** Inside one word, [`crate::Bits::run_starts`] (Hacker's
85//! Delight fig. 6-5): repeat `x &= x >> s` with `s` halving; after
86//! `⌈log₂ k⌉` steps bit `p` is set iff bits `p..p + k` were all set.
87//! Across the boundary there is exactly one candidate: the word's top
88//! run of ones (`leading_ones`) continued by the next word's bottom run
89//! (`trailing_ones`). No wider window is needed; an earlier version
90//! of this kernel widened to `u128` and was 1.6–2.2× slower for it.
91//! Shipped as [`crate::slice::find_run`].
92//!
93//! ```
94//! use hakmem::slice::find_run;
95//!
96//! // 60 free slots, then 4 taken, then all free: a 6-run must straddle.
97//! let words = [u64::MAX >> 4, u64::MAX];
98//! assert_eq!(find_run(&words, 6), Some(0));
99//! let words = [0xFFu64 << 56, u64::MAX];
100//! assert_eq!(find_run(&words, 16), Some(56));
101//! ```
102//!
103//! **Laws.** `run_starts_composes`: `run_starts(a) ∘ run_starts(b) =
104//! run_starts(a + b − 1)`. This is *why* the halving chain is
105//! correct, each halving step is a composition. `run_starts_shrinks`
106//! (longer runs start at a subset of positions) is what makes binary
107//! search for [`crate::Bits::longest_run`] valid. `slice_ops_match_reference`
108//! covers the boundary case.
109//!
110//! **Cost.** ≤ 6 operations per word for `k ≤ 64` plus two count-ones
111//! at a boundary; the scan is memory-bound, not ALU-bound.
112//!
113//! # 3. The Myers column step
114//!
115//! **Problem.** Levenshtein distance is a dynamic-programming table;
116//! compute it without touching cells one at a time.
117//!
118//! **Decomposition.** Adjacent cells in a DP column differ by −1, 0 or
119//! +1, so a column of `m` cells is two `m`-bit words: `Pv` (delta +1)
120//! and `Mv` (delta −1). Matches of the next text character are a mask
121//! `Eq`. The step is
122//!
123//! ```text
124//! Xh = ((Eq & Pv) + Pv) ^ Pv | Eq     // matches propagate down the column
125//! Ph = Mv | !(Xh | Pv)                // horizontal deltas out
126//! Mh = Pv & Xh
127//! score += top bit of Ph, −= top bit of Mh
128//! Pv = (Mh << 1) | !(Xv | (Ph << 1))  // shift deltas one row down
129//! Mv = (Ph << 1) & Xv
130//! ```
131//!
132//! The addition is the whole trick: a carry chain is a scan, and the
133//! DP's "a match at row `i` lets the score at row `i+1` stay flat"
134//! is exactly carry propagation. The DP boundary `D[0][j] = j` is one
135//! bit shifted into `Ph` (global) or not (semi-global search). Shipped
136//! as [`crate::myers`], written against [`crate::Word`] so that
137//! [`crate::wide::Wide`] runs it unchanged for long patterns.
138//!
139//! ```
140//! use hakmem::myers::{edit_distance, search};
141//!
142//! assert_eq!(edit_distance::<u64>(b"kitten", b"sitting"), Some(3));
143//! let ends: Vec<_> = search::<u64>(b"lo", b"hello lo", 0).unwrap().collect();
144//! assert_eq!(ends, [(5, 0), (8, 0)]);
145//! ```
146//!
147//! **Laws.** None of the exported ones, the kernel is verified against
148//! the textbook DP by property tests on `u8`, `u64`, `u128` and
149//! `Wide<4>` (`tests/myers.rs`). That is the honest way to say "this
150//! sentence has no local algebraic proof, only a global one".
151//!
152//! **Cost.** ~12 operations per text byte, independent of pattern
153//! length up to the word width; `N` limbs for `Wide<N>`.
154//!
155//! # 4. Morton neighbours without decoding
156//!
157//! **Problem.** Cells of a 2D grid are stored in Z-order (Morton
158//! codes). Step to the east neighbour without splitting the code into
159//! `(x, y)` and back.
160//!
161//! **Decomposition.** A Morton code interleaves `x` and `y`, so `x`
162//! lives in the even bits, a *dilated* integer. Adding one to a
163//! dilated integer must carry across the zero gaps: fill the gaps with
164//! ones first, add, mask back. [`crate::Dilated::incr`] does exactly that,
165//! and [`crate::Dilated`] has no `+` on purpose, plain integer addition on
166//! a dilated value is the bug this type makes uncompilable.
167//!
168//! ```
169//! use hakmem::Morton2;
170//!
171//! let m = Morton2::<u32>::encode(3, 5);
172//! assert_eq!(m.step_x().decode(), (4, 5));
173//! assert_eq!(m.step_y().decode(), (3, 6));
174//! ```
175//!
176//! **Laws.** `dilated_incr_is_add_one`, `dilated_add_is_add`
177//! (dilation is a homomorphism of addition modulo the width),
178//! `morton_steps_are_unit_moves`, `morton_aligned_block_is_contiguous`
179//! (aligned power-of-two blocks are contiguous code ranges, the
180//! reason a 1D allocator can run over a 2D texture).
181//!
182//! **Cost.** `incr` is three operations; `encode` / `decode` are two
183//! PDEP / PEXT, or a five-step spread without BMI2.
184//!
185//! # 5. `strlen` in one word
186//!
187//! **Problem.** Find the first zero byte of a word, the inner loop of
188//! `strlen`, `memchr` and every delimiter scan.
189//!
190//! **Decomposition.** [`crate::Bits::zero_bytes`] sets the high bit of every
191//! zero lane, exactly: `!((x & 0x7f…) + 0x7f… | x | 0x7f…)`. The
192//! classic `(x − 0x01…) & !x & 0x80…` is one operation shorter and
193//! *wrong* above the first zero byte (a borrow leaks into the next
194//! lane); it is fine for "is there any", not for "which". Then
195//! `trailing_zeros / 8` names the lane. [`crate::Bits::bytes_eq`] is the
196//! same sentence after `x ^ splat(b)`.
197//!
198//! ```
199//! use hakmem::Bits;
200//!
201//! let word = u64::from_le_bytes(*b"hello\0!!");
202//! assert_eq!(word.first_zero_byte(), Some(5));
203//! assert_eq!(word.bytes_eq(b'l').count_ones(), 2);
204//! ```
205//!
206//! **Laws.** `swar_lanes_match_reference` (every lane predicate against
207//! a byte loop, exhaustive over all bytes for `u8`/`u16`);
208//! `zero_bytes_turns_or_into_and` (a lane is zero in `x | y` iff zero
209//! in both), the De Morgan shape that lets you test two words with
210//! one scan.
211//!
212//! **Cost.** Four operations for the mask, one `trailing_zeros` for
213//! the index; eight bytes per iteration instead of one.
214//!
215//! # 6. Sliding-piece attacks (Kogge–Stone)
216//!
217//! **Problem.** On an 8×8 bitboard, which squares does a rook attack
218//! northward, given the occupied squares?
219//!
220//! **Decomposition.** "Slide until blocked" is a prefix OR along a
221//! stride of 8 through a propagation mask (the empty squares):
222//! [`crate::Bits::fill_up`]. Kogge–Stone doubles the stride each round
223//! (`gen |= prop & gen << s; prop &= prop << s`), three rounds for
224//! eight ranks. The attacked set includes the blocker: shift the fill
225//! once more.
226//!
227//! ```
228//! use hakmem::Bits;
229//!
230//! let rook = 1u64; // a1
231//! let occupied = 1u64 << 32; // a5
232//! let attacks = rook.fill_up(!occupied, 8) << 8;
233//! assert_eq!(attacks & 0x0101_0101_0101_0101, 0x0000_0001_0101_0100); // a2..a5
234//! ```
235//!
236//! **Laws.** `fills_match_reference` (the doubling rounds equal
237//! iterating single steps), `fills_are_closure_operators` (idempotent
238//! and extensive, filling twice is filling once, which is what makes
239//! "occupancy changed only here" updates safe). With a full mask and
240//! stride 1, `fill_up` *is* `prefix_or`.
241//!
242//! **Cost.** Three rounds of three operations per direction; the
243//! eight directions of a queen are 72 operations, no table.
244//!
245//! # 7. Not built here: banded Myers over `Wide<N>`
246//!
247//! For two long strings that differ in few edits, `triple_accel`
248//! beats recipe 3 on `Wide<8>` by about 2× (see the README table),
249//! because it only computes a diagonal band. This crate does not ship
250//! that variant, deliberately. Everything needed is here.
251//!
252//! A `Wide<N>` column is `N` limbs. Run the step of recipe 3 per limb
253//! with an explicit horizontal delta between limbs: the top bit of
254//! `Ph` / `Mh` leaving limb `i` is the bit shifted into limb `i + 1`
255//! (this is exactly what [`crate::Word::wrapping_add`] does across limbs
256//! implicitly, the banded version makes the carry explicit so it can
257//! stop). Keep the score of the last active limb's bottom cell; while
258//! it exceeds `k + (limbs left) × 64`, the limbs below it cannot come
259//! back under `k` and need not be updated (Ukkonen's cut-off, Hyyrö's
260//! block formulation). Cost drops from `N` limbs per text byte to the
261//! active band, typically one or two. The laws you would write:
262//! agreement with recipe 3 on the same inputs when `k` is large, and
263//! `None`-agreement with the DP when it is small. Both are one
264//! proptest each against `tests/myers.rs`'s reference. Do that and you
265//! have your microkernel; it will be shorter than this paragraph.
