Dilated integers and Morton (Z-order) codes.

A dilated integer keeps its bits at every D-th position, zeros between. Interleaving D of them gives a Morton code, the address space where a 2^n × 2^n grid’s aligned power-of-two blocks are contiguous ranges, the reason a 1D allocator can run over a 2D texture.

Arithmetic on dilated values does not go through +: the gaps must be filled with ones so the carry tunnels across them (((a | !mask) + b) & mask, Wise & Raman). Dilated therefore has no Add impl, only incr and wrapping_add. Plain integer addition on it does not compile, and this block is the proof:

ⓘ
use hakmem::prelude::*;

let x = Dilated::<u64, 2>::from_int(5);
let _ = x + x; // the gaps would carry into the other coordinate

What does compile:

use hakmem::prelude::*;

let x = Dilated::<u64, 2>::from_int(5);
assert_eq!(x.wrapping_add(x).to_int(), 10);
