Module isa 

Source
Expand description

Instruction sets as values: pick one where a hot loop starts, pass it down, and the primitives inside compile to its instructions.

A token is a zero-sized proof that the CPU has a set of features. Portable and Native exist everywhere; X86V2, X86V3 and X86V4 (x86) only come out of detect (or an unsafe promise). Isa::run runs a closure compiled with the token’s features, and dispatch! does the detection and the run in one go:

use hakmem::isa::Isa;

fn gather<I: Isa>(cpu: I, xs: &[u64], mask: u64) -> u64 {
    xs.iter().fold(0, |a, &x| a ^ cpu.pext(x, mask))
}

let xs = [0b1011u64, 0b0110];
let r = hakmem::dispatch!(|cpu| gather(cpu, &xs, 0b0110));
assert_eq!(r, 0b01 ^ 0b11);

Detection happens once per dispatch!, so it belongs above the loop, not in it. Everything the closure calls has to inline into it: a helper kept out of line (#[inline(never)], or too big for LLVM’s taste) is compiled without the features, and each primitive in it becomes a call. Design notes, section 3.
